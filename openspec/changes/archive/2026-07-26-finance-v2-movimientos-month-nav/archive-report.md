### Issues Found and Fixed (Post-Review)

A 4-reviewer pass on PR1 identified and fixed 5 items before handoff:

1. **BLOCKER — A→B→A round-trip data corruption**: early-return guard in re-fetch effect allowed in-flight requests to overwrite newer state when the user navigated back to an already-loaded month before intervening month's load resolved. Fixed via effect cleanup function that always bumps `requestIdRef` before next invocation.
2. **CRITICAL — Fabricated precedent comment**: `viewedMonth`/`setViewedMonth` comment incorrectly cited non-existent "`expense-unit-multiplier` precedent". Rewritten to state the honest reason: unused until PR2 wires it into controls.
3. **WARNING — Non-discriminating test**: `"cross-month add during a pending load"` case used month differing from both `viewedMonth` and `loadedMonthRef`, so didn't prove the routing fix. Changed transaction month to match `viewedMonth` so test forks correctly between old and new routing.
4. **SUGGESTION — Redundant wrap**: Simplified `Promise.resolve(onLoad(month)).then(...)` to `onLoad(month).then(...)`.
5. **Observability**: Added `console.error` in `onLoad` rejection path for debugging real failures.

**Post-fix verification**: `npm run test` → 684/684 passed (+1 new A→B→A regression test); `tsc --noEmit` → clean; `npm run build` → success.
